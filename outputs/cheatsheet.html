1Project Overview

APiWiki is an internal, on-premises "Knowledge Wiki" for APi Group used to capture, browse, validate, and search business-process rules, reference articles, Small Enhancement Documents (SEDs), and video guides extracted from source documents (PDF/DOCX/TXT/VTT). It exists to satisfy SOX compliance requirements: every change to rules, workflows, articles, SEDs, and videos is written to an append-only audit_log table with previous/new JSON values. Content is multi-tenant, scoped per company, with role-based access (viewer < validator < editor < admin/developer/super_admin/company_admin). Users upload source documents; a Python/FastAPI ingestion pipeline extracts structured rules (via a LangGraph + LLM pipeline) or converts documents into articles/SEDs, then the Next.js wiki app lets stakeholders browse workflows, validate rules, flag gaps, chat with an AI assistant grounded in hybrid (full-text + vector) search, and manage users/companies/platforms as an admin. Everything runs self-hosted via Docker Compose behind Traefik — no Vercel, no external SaaS APIs beyond an optional "NaN Builders" LLM inference endpoint used instead of local Ollama.

3Architecture Map

Ingestion (write) path:

User uploads file (app/upload page) → app/api/upload/{process|article|sed|video}/route.ts (role-checked, forwards multipart) → pipeline (FastAPI) POST /ingest, /ingest/sed → document loaded/chunked (pipeline/ingest/) → for rule docs: LangGraph pipeline (pipeline/extract/pipeline.py) extracts + dedupes rules via LLM → pipeline/db/client.py writes rows to Postgres (rules/articles/seds) + audit_log → pipeline fires a background HTTP call back to the wiki's own /api/embed, /api/articles/embed, or /api/seds/{id}/embed endpoints, which call lib/ollama.ts embed() and update the row's embedding column. Video guides skip the pipeline entirely — app/api/upload/video/route.ts calls the LLM chat-completions endpoint directly from Next.js using a parsed VTT transcript (lib/vtt.ts).

Read / query path:

Browser → middleware.ts (session cookie check via internal /api/auth/me call, RBAC path gating, injects x-user-* headers) → page/route handler → lib/db.ts (plain SQL) or lib/search.ts hybridSearch() (parallel Postgres full-text-search + pgvector KNN, merged via Reciprocal Rank Fusion) → Postgres → JSON response rendered by React pages.

Auth path: login → password check (lib/auth.ts) → temp token (wiki_temp cookie) → 2FA (TOTP or email code) → session created (wiki_session cookie, 8h, SHA-256-hashed token stored in sessions table) → every subsequent request re-validated both in middleware.ts and independently inside most route handlers.

5Key Files — Read These First

middleware.ts

Gatekeeper for the entire app. Defines PUBLIC_PATHS, ADMIN_PATHS, VALIDATOR_PATHS; validates the wiki_session cookie by calling internal /api/auth/me; injects x-user-id/email/role headers.

Breaks if changed carelessly: get a path wrong here and you either lock everyone out or expose a route with zero auth.

lib/auth.ts

All auth primitives: password hash/verify, TOTP generate/verify, session create/validate/delete, temp-token flow, email 2FA, password reset.

Breaks if changed: session validation, login, 2FA, and password reset all depend on this file directly.

lib/db.ts

pg.Pool singleton + core query helpers (getAllWorkflowsWithStats, getUserCompanyIds, etc.) used across nearly every route.

Breaks if changed: connection config or helper signature changes ripple into most app/api/ routes.

lib/ollama.ts

Single abstraction over local Ollama vs. remote "NaN Builders" LLM API for both chat and embeddings; branches on whether OLLAMA_BASE_URL is remote/has an API key.

Breaks if changed: chat streaming, embeddings, hybrid search relevance, and the backfill script all depend on this.

lib/search.ts

hybridSearch() — merges Postgres full-text search and pgvector KNN across rules/articles/seds via Reciprocal Rank Fusion. Powers /api/search and the search page.

Breaks if changed: search result ranking/coverage; silently degrades to FTS-only if the embed call fails.

scripts/migrate.ts

Canonical schema definition (idempotent CREATE TABLE IF NOT EXISTS/ADD COLUMN IF NOT EXISTS) plus seed data for companies/platforms/categories.

Breaks if changed: this IS the schema — there's no separate ORM/migration framework. Miss a column here and the app 500s at runtime.

pipeline/api/routes.py

796-line FastAPI route file: /ingest, /ingest/text, /ingest/sed, HTML conversion, SED field extraction (extract_sed_data).

Breaks if changed: all document ingestion (rules, articles, SEDs) flows through this one file.

pipeline/extract/pipeline.py

LangGraph state machine: extract-from-chunk (looped) → deduplicate → write-to-db. Talks to the LLM directly via httpx, not the OpenAI SDK.

Breaks if changed: rule extraction quality/dedup and what actually lands in the rules table.

pipeline/db/client.py

Raw psycopg2 client: workflow/rule/article/SED inserts, all paired with explicit audit_log writes, plus the callbacks that trigger embedding generation on the wiki side.

Breaks if changed: SOX audit trail integrity from the pipeline side, and the embed-callback chain (miss it → row has no embedding, invisible to semantic search).

7Non-Obvious Patterns

Auditing is app-code-only, not DB-enforced. DB triggers for audit_log were deliberately dropped (per scripts/migrate.ts comments); every INSERT/UPDATE/DELETE on audited tables must explicitly call an audit-log insert in TypeScript or Python. A route that forgets this silently breaks the SOX trail — app/api/workflows/[id]/narrative/route.ts (PATCH) appears to have no audit_log write and no visible auth check.
Embeddings are 4096-dim and unindexed. Originally vector(768), migrated in-place to vector(4096) (existing embeddings nulled since dims are incompatible). pgvector's ivfflat/hnsw indexes cap at 2000 dims, so no ANN index exists — vector search is exact brute-force KNN. This is a stated tradeoff in the migration script itself, worth knowing before assuming search is O(log n).
Rate limiting is in-memory, per-process. Login/2FA/forgot-password rate limiters use plain JS Maps in each route file — they reset on every deploy/restart and don't share state across horizontally scaled replicas. Effective for a single-container deploy only.
Possible residual cache-header conflict on uploads. next.config.ts's headers() still sets Cache-Control: public, max-age=31536000 on /uploads/:path*, while app/api/uploads/[...path]/route.ts sets private, no-store. Which one wins wasn't verified — worth checking directly if upload confidentiality matters (SOX documents).
Pipeline dependency pin may leave a HIGH CVE open. pipeline/requirements.txt pins fastapi==0.115.0, below the security audit's recommended fastapi>=0.115.6/starlette>=0.40.0 fix for the authz-bypass finding — unconfirmed whether the transitively installed starlette version is actually patched.
Two parallel auth-check styles coexist. middleware.ts injects x-user-id/email/role headers after validating the session, but most route handlers also independently re-validate the wiki_session cookie via lib/auth.ts validateSession() rather than trusting the headers alone (this was a fix applied per the security audit). A few admin routes still redundantly check both.
Role checks are ad-hoc per-route, not centralized. Arrays like ["editor","admin","developer"] are repeated inline across many app/api/*/route.ts files rather than defined once as a shared constant/helper — easy to accidentally omit a role in one route and not another.
Video guides bypass the Python pipeline entirely. Unlike every other content type, app/api/upload/video/route.ts calls the LLM's chat-completions endpoint directly from Next.js (using lib/vtt.ts to parse WebVTT transcripts) instead of forwarding to FastAPI. If you're debugging video ingestion, don't look in pipeline/ — look here.
Multi-tenancy is filter-based, not row-level-security. Company scoping (company_id, is_corporate, user_companies) is enforced by adding WHERE clauses in application queries (getUserCompanyIds in lib/db.ts) — bypassed entirely for admin/super_admin/developer roles. There is no Postgres RLS backstop; a query that forgets the filter will leak cross-company data.
Two-step login flow uses a separate short-lived cookie. Between password verification and 2FA completion, a wiki_temp cookie (5-min expiry, temp_tokens table) tracks in-progress login state — distinct from the final 8-hour wiki_session cookie. Relevant when debugging "stuck on 2FA" issues.
